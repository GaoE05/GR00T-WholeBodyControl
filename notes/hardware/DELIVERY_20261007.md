## Patch 的用法

`patches/000*.patch` 是本次报告分支从 base `163d7f4cab0585ce16488bf596f2c8ff4a4d9f63` 起的全部相关提交，依序 `git am`。例如在协调端目标仓库（保留它的已有修改）选择干净工作副本：

```bash
git switch -c codex/general32-hardware-results-20261007 163d7f4cab0585ce16488bf596f2c8ff4a4d9f63
git am /绝对路径/解包目录/patches/000*.patch
```

若现有分支名称已被占用，采用新的报告分支名；遇报告路径冲突逐块合并，保留协调端已有材料。`git am` 可能因 committer/time 生成不同 commit SHA，回传时同时注明本包源 HEAD 和协调端新 HEAD。patch 仅增加/修改轻量报告材料，不修改控制器、模型、gains/scales 或训练任务。此次包内 `controller_playback_diff_842cab_to_d9d9a7f.patch` 是**作为报告附件归档的旧现场源码 diff**，不要额外拿它给协调端/现场控制器打补丁。

大视频、模型、binary、reference CSV、原始日志和完整 FK CSV 不在 ZIP。离线分析脚本依赖现场现有 numpy/mujoco、原数据绝对路径，仅使用 `mj_forward`，不会启动 DDS；协调端无需重跑分析才能审阅结果。
